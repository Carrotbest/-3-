# R114 GD 작지 옵션 단위를 Part+Color 로 되돌림

상태: 구현 완료, 검증 완료. 커밋 전.

## 증상

신규 작지 접수에서 `Fabric sample request report_FSR260901105_KOLORI.xlsx` 를 첨부하면 옵션이 2건만 잡혔다.
이 작지는 BODY 6개(B01~B06)에 색상 2개(REAL HTHR GREY, REAL HTHR PINK)라 12건이 맞다.

## 원인

`src/data/zaji.ts` 의 `parseGd` 가 옵션 단위를 색상 번호(No)로 잡고, 한 색상에 걸린 Part 를 대표 1건으로 접고 있었다.
2026-08-28 커밋 `8ef8dba` 에서 들어간 변경이다. 커밋 메시지는 "병합된 Part 하위행을 대표 1건으로 접어 중복 옵션 방지"였다.

이 접기는 원본 구현과 다르다. `zaji.ts` 1~3행 주석이 "파싱 로직은 원본과 동일하게 유지한다(... Part+Color 중복 제거)" 라고 못박고 있는데 그것을 어긴 상태였다.

원본은 `업무 자동화/작지변환기_배포/zaji/parser.py` 의 `parse_gd` 다. 옵션 단위가 Part+Color 이고, 병합 셀로 **같은** Part+Color 가 반복될 때만 1건으로 합친다. 서로 다른 Part 는 접지 않는다.

## 근거 수치

두 구현을 같은 파일에 돌린 결과다.

| 파일 | 원본 parser.py | 수정 전 웹 | 수정 후 웹 |
|---|---|---|---|
| FSR260901105_KOLORI | 12건 (dup 0) | 2건 | 12건 (dup 0) |
| FSR260801240 | 5건 (dup 0) | 1건 | 5건 (dup 0) |

수정 후 웹 결과는 Part, Color, Weight, Dyeing 까지 원본과 순서대로 일치한다.

FSR260801240 도 색상이 `TBD` 하나뿐이라 옛 로직에서는 5개 Part 가 1건으로 접히고 있었다. 이 파일도 같이 고쳐졌다.

## 조치

`src/data/zaji.ts` 268~293행을 원본과 같은 Part+Color 루프로 교체했다. 다른 파일은 건드리지 않았다.

- 색상 번호(No) 기준 그룹핑 삭제
- 대표 Part 선정 로직(`byQty`, `byDye`, `chosen`) 삭제
- `seen` 집합으로 같은 `part::color` 반복만 `dupRemoved` 로 집계

## 알려진 절충

같은 색상에 같은 원단이 염색 변형(DD/SD)으로 두 줄 잡힌 작지가 있으면 이제 옵션 2건으로 올라온다. 접수 팝업에서 한 건을 지우면 된다.
원본 변환기도 같은 동작이므로 기준을 원본에 맞춘 것이다. 다시 접기를 넣으려면 그 작지 파일을 먼저 확보해서 회귀 케이스로 남겨야 한다.

## 검증

- `npm run build` 통과.
- `src/data/zaji.ts` 를 esbuild 로 번들해 노드에서 실행, 위 표의 수치를 직접 확인.

## 하지 말 것

- 옵션 단위를 다시 색상 번호(No)로 바꾸지 마라. 이 문서가 그 사고 기록이다.
- `zaji/parser.py` 와 다르게 만들지 마라. 원본이 기준이다.
