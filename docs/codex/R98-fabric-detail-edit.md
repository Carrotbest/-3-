# R98 — 원단 상세 재구성과 직접 수정

상태: 구현 완료(클로드 직접 시공, Codex 한도 소진). 화면 확인만 남음.

## 사용자가 정한 것

- 재고 셀은 한 번 클릭에 팝업이 뜨면 안 된다. 수정 창이 가려진다.
- 원단 상세 상단에 재고 전체·잔량을 띄우고, 모든 항목을 그 자리에서 고칠 수 있어야 한다.
- 상세에서 고친 값은 DD MASTER의 같은 옵션 행과 함께 움직여야 한다.
- 공정 날짜는 필요 없다. 대신 샘플 완료일, 입고일, Remark, Review, 축률 같은 실무 값을 보여준다.
- 이력은 유지하되 줄을 최대한 적게 쓴다.
- 개발 섹션에 원사 정보를 넣는다.

## 조치

### 저장 경로

`saveFabricField(item, field, value)`(`src/store/useAppStore.ts`)가 두 갈래로 나눈다.

| 행 종류 | 저장 위치 | 결과 |
|---|---|---|
| DD 레코드가 붙은 행 | `DevRecord` (`saveDevelopmentRecord`) | DD MASTER의 같은 행이 함께 바뀐다 |
| 샘플관리대장 전용 행 | `FabricLedgerOverride.fields` | 창고 화면에만 반영되고 대장 원본은 그대로 |

창고 수량(전체 yds, 잔량)과 R&D No.는 개발 데이터가 아니므로 종전처럼 `applyFabricAction`으로 오버라이드에 쓴다. 잔량을 고치면 전체 = 잔량 + 반출 합계로 역산한다.

### 데이터

`FabricLedgerItem.fields`를 새로 만들었다. DD `tech`와 대장 원문에서 실무 값을 끌어오고, 대장 전용 행은 `override.fields`로 덮는다. 키 목록은 `FABRIC_FIELD_IDS`다. `override.fields`의 본문 필드(Buyer, 중량 등)는 원장 항목에도 얹혀 창고 목록에서도 바뀐 값이 보인다.

### 수정 방식

칸마다 클릭해 고치는 방식은 버렸다. 상단 **수정** 버튼으로 편집 모드에 들어가고, **확인**으로 한 번에 저장하며 **취소**로 되돌린다. 저장은 한 번만 일어나므로 칸마다 중앙으로 올라가지 않는다.

R&D No.도 고칠 수 있다. 저장 전에 다른 원단이 그 번호를 쓰고 있는지 검사하고, 겹치면 저장하지 않고 알린다. 전체 yds를 비우면 재고를 지운다(`clearYds`).

읽기 전용은 반출 합계(출고 이력의 합)와 입고일(이벤트 기록) 둘뿐이다.

### 화면

- 상단: FL#, Style No., R&D No., 상태 + 전체 yds, 반출 합계, 잔량.
- 원단: 조직, 목표 중량, 실측 중량, 폭, 축률 경·위, Color, Dyeing, 원사, Remark, 공정 업체 네 칸. 공정 날짜 표는 뺐다.
- 분류·의뢰: Season, Category, Buyer, 담당, Planner, 접수일, 납기, 샘플 완료일, FDS, YDS, 입고일, Pass/Fail, Review.
- 창고 팝업 폭을 화면의 96%까지 넓혔다(최대 1600px).
- 반출: 표 유지, 행 높이만 줄였다.
- 이력: 한 건을 한 줄로 줄였다. 날짜, 동작, 상태 변화, 비고 순이다.
