# R77. FABRIC TREND 카드 클릭 정합성, 패싯 수치, 핫클립

상태: **원인 규명 완료, 구현 미착수**. Codex가 구현한다.

R76이 끝난 뒤에 착수한다. 같은 워킹트리를 동시에 건드리지 않는다.
R76은 MACRO(`TrendMacro.tsx`, `tools/trend`)를, R77은 FABRIC(`TrendFabric.tsx`)을 다룬다.

`npm run build` 통과 상태를 유지한다. 커밋과 푸시는 하지 않는다.

대상 파일은 `src/routes/TrendFabric.tsx` 하나다. 파이썬과 `feed.json` 구조는 바꾸지 않는다.

# 1. 상단 카드를 눌러도 숫자가 안 맞는다

## 증상

카드에 적힌 수와 클릭 후 목록에 나오는 수가 다르다. 실측값이다.

| 카드 | 표시 | 클릭 후 목록 | 차이 |
|---|---|---|---|
| 최근 30일 소재 기사 | 132 | 158 | +26 |
| 최근 7일 소재 기사 | 83 | 105 | +22 |
| 급상승 키워드 리사이클 | 12 (최근 4주) | 기간이 30일이면 12, 전체면 15 | 기간에 따라 달라짐 |

"직관적이지 않고 떨어진 느낌"의 정체가 이거다. 누른 숫자와 받은 숫자가 다르니 연결이 안 느껴진다.

## 원인 둘

**원인 A. 게이트가 필터 차원에 없다.**

카드는 관련도 소재 게이트(`article.w === "material"`)로 센다.
그런데 목록 필터에는 `range`, `category`, `tag`, `media`, `starOnly`, `needle`만 있고 게이트가 없다.
그래서 카드1을 누르면 `range=30`만 걸리고 유통 기사 26건이 그대로 딸려 온다.

**원인 B. 기존 필터가 남는다.**

카드 클릭이 자기 필터만 세팅하고 나머지는 그대로 둔다.
직전에 태그나 매체를 골라 뒀으면 그게 살아 있는 채로 카드 필터가 얹힌다.
사용자는 카드를 눌렀는데 엉뚱하게 좁혀진 목록을 본다.

## 조치

**A. `gate` 필터 상태를 추가한다.**

```
const [gate, setGate] = useState<"material" | "retail" | null>(null)
```

`visible`의 필터 체인에 한 줄 넣는다.

```
if (gate && article.w !== gate) return false
```

`useEffect(() => { setLimit(PAGE) }, [...])`의 의존성 배열에도 `gate`를 넣는다.
`reset()`에서도 `setGate(null)`을 한다.

**B. 카드 클릭은 필터를 통째로 갈아 끼운다.**

헬퍼를 하나 만든다. 이름은 `applyCardFilter` 정도가 좋다.

```
const applyCardFilter = (next: {
  range?: number
  gate?: "material" | "retail" | null
  tag?: string | null
}) => {
  setCategory(null); setMedia(null); setStarOnly(false); setQuery(""); setSort("recent")
  setRange(next.range ?? 30)
  setGate(next.gate ?? null)
  setTag(next.tag ?? null)
  setTab("all")
}
```

핵심은 **먼저 전부 지우고 카드가 지정한 것만 건다**는 점이다.
이래야 카드에 적힌 수와 목록 수가 항상 같다. 이게 이번 작업에서 가장 중요한 한 가지다.

카드별 호출은 이렇게 된다.

| 카드 | 호출 |
|---|---|
| 최근 30일 소재 기사 | `applyCardFilter({ range: 30, gate: "material" })` |
| 최근 7일 소재 기사 | `applyCardFilter({ range: 7, gate: "material" })` |
| 급상승 키워드 (1~3위 공통) | `applyCardFilter({ range: 30, tag: <해당 태그> })` |
| 저장된 기사 | 지금처럼 `setTab("saved")` |

급상승 키워드에 `range: 30`을 주는 이유가 있다. 모멘텀은 28일 기준이고 캡션에 "최근 4주 12건"이라 적힌다.
기간을 30일로 맞춰야 목록이 12건으로 떨어져 캡션과 일치한다.
기간을 안 건드리면 전체(120일)일 때 15건이 나와 또 어긋난다.

**C. 필터 패널에 게이트 칩을 노출한다.**

`FilterPanel`에 "소재만 / 유통만" 칩을 추가한다. 기간 칩 옆이 자연스럽다.
게이트가 걸려 있는데 화면에 그 사실이 안 보이면, 사용자는 목록이 왜 좁은지 알 수 없다.
다시 누르면 해제되게 한다(`gate === "material" ? null : "material"`).

**D. `pressed` 판정을 고친다.**

지금 카드1과 카드2의 `pressed`가 `tab === "all" && range === 30` 같은 식이라
서로 간섭하고 게이트를 안 본다. `gate === "material" && range === 30 && tab === "all"`처럼
카드가 실제로 건 조건 전체와 비교한다.

# 2. 필터 숫자와 목록 숫자가 안 맞는다

## 증상

사이드바 분류·태그 옆 숫자가 실제 목록 건수와 다르다. 실측값이다.

| 분류 | 사이드바 표시 | 30일 목록 실제 | 차이 |
|---|---|---|---|
| MATERIAL | 71 | 50 | -21 |
| FABRIC | 52 | 43 | -9 |
| ETC | 29 | 22 | -7 |
| CHEMICAL | 20 | 15 | -5 |
| YARN | 5 | 2 | -3 |
| RETAIL | 27 | 26 | -1 |
| **합계** | **204** | **158** | |

태그도 같다. `리사이클` 15 대 12, `바이오소재` 7 대 3이다.

## 원인

`feed.facets.categories`, `.tags`, `.sources`는 `publish.py`가 **120일 창 전체**로 미리 계산한 고정값이다.
화면 기본 기간은 30일이다. 게다가 태그·매체·검색어·별표 필터가 걸려도 이 숫자는 꿈쩍하지 않는다.

즉 사이드바는 "전체 창에 이만큼 있다"를 말하고, 목록은 "지금 조건에 이만큼 있다"를 말한다.
둘이 다른 질문에 답하고 있다.

## 조치

`feed.facets`를 화면 표시용으로 쓰지 않는다. 현재 필터 상태에서 직접 센다.

패싯 카운트의 정석은 **자기 차원을 뺀 나머지 필터를 적용해서 세는 것**이다.
분류 숫자를 낼 때는 분류 필터만 빼고 기간·태그·매체·검색·별표·게이트를 모두 적용한다.
그래야 그 숫자가 "이걸 누르면 나올 건수"와 정확히 같아진다.

구현은 필터 술어를 차원별로 쪼개 놓고 조합하는 방식이 깔끔하다.

```
const passes = (article, skip: "category" | "tag" | "media" | null) => {
  if (article.d < since) return false
  if (gate && article.w !== gate) return false
  if (skip !== "category" && category && article.c !== category) return false
  if (skip !== "tag" && tag && !article.g.includes(tag)) return false
  if (skip !== "media" && media && article.m !== media) return false
  if (starOnly && !stars.has(article.id)) return false
  if (needle && !`${article.t} ${article.o} ${article.s}`.toLowerCase().includes(needle)) return false
  return true
}
```

`visible`은 `passes(article, null)`을 쓰고, 분류 카운트는 `passes(article, "category")`로 거른 뒤
`article.c`로 집계한다. 태그와 매체도 같은 방식이다. `useMemo`로 묶어 한 번만 돈다.

표시 규칙 두 가지를 지킨다.

- 0건인 분류는 숨기지 말고 0으로 두되 눌리지 않게 한다. 항목이 사라졌다 나타나면 위치가 흔들려 읽기 나쁘다
- 태그는 지금처럼 상위 22개를 보여 주되, **현재 조건에서의 건수 기준**으로 다시 정렬한다.
  고정 목록을 그대로 두면 0건 태그가 상단을 차지한다

# 3. 우측 목록 제목이 필터를 반영하지 않는다

지금은 무슨 필터를 걸든 제목이 항상 "신소재 피드"다. 무엇을 보고 있는지 알 수 없다.

활성 필터에서 제목을 만든다. 우선순위는 좁은 것부터다.

| 조건 | 제목 |
|---|---|
| 태그 선택 | `리사이클 태그 기사` |
| 분류 선택 | `MATERIAL 기사` |
| 매체 선택 | `<매체명> 기사` |
| 게이트만 | `소재 기사` 또는 `유통 기사` |
| 아무것도 없음 | `신소재 피드` |

여러 개가 동시에 걸릴 수 있다. 그때는 위 우선순위로 하나만 쓰고,
건수는 제목 옆에 `12건`처럼 붙인다. 제목이 길어지면 목적을 잃는다.

# 4. 제목 아래 설명과 각주를 없앤다

정렬 기능은 남긴다. 지울 것은 설명 문구뿐이다.

**지울 것 1.** `신소재 피드` 아래 `CardDescription` 전체.

```
{visible.length}건 · 제목 한국어 변환 {feed.translated}건 · 수집 {generated_at}
```

건수는 3번에서 제목 옆으로 옮긴다. 번역 건수와 수집 시각은 실무에 안 쓰인다.

**지울 것 2.** 정렬 칩 옆 HIT 설명 문구 전체.

```
HIT는 같은 기사를 다룬 매체 수입니다. RSS는 조회수를 주지 않습니다. 최근 30일 2곳 이상이 ... 11건.
```

이걸 지우면 `hitCount` useMemo를 쓰는 곳이 없어진다. 같이 지운다.
정렬 칩의 `HIT순`은 `SORTS`에 있으므로 그대로 남는다.

**지울 것 3.** `최근 30일 기사 분류` SectionCard의 `subtitle`.

```
분류별 기사 수를 같은 축에서 비교합니다. 막대를 누르지 않아도 우측 수치로 정확한 건수를 확인할 수 있습니다.
```

제목만 남긴다.

**남길 것.** 정렬 라벨과 칩 3개(`최신순`, `HIT순`, `관련도순`), 검색 입력창.

# 5. 급상승 키워드를 핫클립으로

## 지금

`StatCard`의 `visual` 슬롯에 2·3위가 글자와 숫자로만 나열된다. 눈에 안 걸린다.

## 쓸 수 있는 재료

기사에 `i`(대표 이미지 URL) 필드가 있다. 실측 커버리지가 충분하다.

```
전체       204건 중 이미지 134건 (66%)
리사이클    15건 중 11건
제직         5건 중  5건
스판덱스      4건 중  4건
```

상위 태그는 커버리지가 좋아서 그림이 빈 칸으로 남을 걱정이 적다.

## 조치

카드 3의 `visual`을 **핫클립 3개가 가로로 놓인 스트립**으로 바꾼다. 1위도 스트립에 포함한다.
지금은 1위만 큰 글씨로 위에 있고 2·3위가 아래 목록인데, 셋을 같은 형식으로 두는 편이 비교가 쉽다.

클립 하나의 구성은 이렇다.

- 썸네일. 그 태그를 단 기사 중 이미지가 있는 **가장 최근** 기사의 `i`를 쓴다
- 태그명
- 증감. `직전 3 → 최근 12` 형태보다 `+9`가 좁은 폭에서 읽기 쉽다
- 순위 배지 1, 2, 3

**썸네일은 기존 `ArticleThumbnail`을 재사용한다.** 새로 만들지 마라.
72행에 이미 있고, 이미지 로드 실패 시 `onError`로 숨기고 분류 색 그라디언트로 떨어지는 처리가 들어 있다.
`referrerPolicy="no-referrer"`와 `loading="lazy"`도 이미 걸려 있다. 외부 이미지라 이 처리가 중요하다.

이미지가 있는 기사가 하나도 없는 태그는 `ArticleThumbnail`에 `i`가 빈 객체를 넘기면
그라디언트 배경만 나온다. 별도 분기가 필요 없다.

클립을 누르면 `applyCardFilter({ range: 30, tag })`가 돈다.
카드 전체 `onClick`과 겹치므로 클립의 클릭 핸들러에서 `event.stopPropagation()`을 부른다.

## 폭 주의

이 카드는 4분할 그리드의 한 칸이라 좁다. 썸네일은 28~32px 정사각을 넘기지 않는다.
태그명은 `truncate`를 건다. 좁은 화면에서 클립 3개가 세로로 쌓이면 카드 높이가 튀므로,
`sm` 미만에서는 2개까지만 보이게 하거나 가로 스크롤로 처리한다.

# 검증

```
npm run build
```

화면에서 다음을 순서대로 확인한다. 숫자가 맞는지가 이번 작업의 합격 기준이다.

1. 카드1을 누른다. 목록 건수가 카드의 132와 같아야 한다
2. 카드2를 누른다. 83과 같아야 한다
3. 급상승 키워드 클립 1위를 누른다. 캡션의 12와 같아야 한다
4. 카드를 누르기 전에 태그나 매체를 아무거나 골라 둔다. 그 상태에서 카드를 눌러도 위 숫자가 그대로 나와야 한다
5. 사이드바 분류를 하나 누른다. 사이드바에 적힌 그 분류의 숫자와 목록 건수가 같아야 한다
6. 기간을 7일로 바꾼다. 사이드바 숫자가 전부 따라 줄어야 한다
7. 우측 제목이 고른 분류·태그·매체 이름으로 바뀌는지 본다
8. 정렬 칩 3개가 남아 있고 그 옆 HIT 설명이 사라졌는지 본다
