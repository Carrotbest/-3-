# R75. FABRIC TREND 상단 KPI 카드 교체

상태: **구현 완료, 화면 검증 미완**. Codex는 아래 "남은 일"만 한다.

`npm run build`(`tsc --noEmit` + vite build) 통과 상태다. 워킹트리 미커밋이다.
커밋은 사용자가 지시할 때만 한다.

현재 코드가 아래 확정 스펙과 일치한다. 카드 값은 `feed.json`으로 검산해 표와 맞는 것을 확인했다.

---

## 배경

기존 상단 4개 카드가 전부 수집기 자기 건강 지표였다.

| 기존 카드 | 값 | 문제 |
|---|---|---|
| 최근 7일 신규 | 105 | 증감 비교가 없어 많은지 적은지 판단 불가 |
| 최근 120일 보관 | 204 | 피드 헤더 `{visible.length}건`과 중복 |
| 분류 판정률 | 86% | 수집기 채점표. 실무자가 이 숫자로 할 일이 없다 |
| 수집 소스 | 32/43 | 하단 "수집 상태" 섹션과 완전 중복 |

이 화면의 질문은 "이번 주 뭘 봐야 하나"인데 넷 중 어느 것도 답하지 않았다.

## 확정 스펙: 상단 카드 4개

`2026-08-31` 수집분(피드 204건) 기준 값을 같이 적는다. 구현 후 검산에 쓴다.

| # | 라벨 | 값 | 캡션 | 클릭 |
|---|---|---|---|---|
| 1 | 최근 30일 소재 기사 | **132** | 피드 158건의 **84%** · 나머지 유통 26건 | `range=30`, `tab=all` |
| 2 | 최근 7일 소재 기사 | **83** | 피드 105건의 **79%** · 나머지 유통 22건 | `range=7`, `tab=all` |
| 3 | 급상승 키워드 | **리사이클** | 최근 4주 12건, 직전 3건 | 1위 태그로 필터, `tab=all` |
| 4 | 저장된 기사 | teamStars 집계 | 팀원 N명이 표시 | `tab=saved` |

### 1·2번: "소재"와 "전체"의 정의

- **소재 기사** = `article.w === "material"`. 관련도 소재 게이트를 통과한 건이다.
  카테고리(`article.c`)가 아니다. 소재 게이트를 통과했지만 카테고리가 `ETC`로 떨어진 건도 포함한다.
- **전체** = 해당 기간 피드에 실린 전량, 즉 `material + retail`이다.
  수집 전량(노이즈 포함)이 아니다.

수집 전량을 분모로 쓰는 안(30일 29%, 7일 34%)은 검토했다가 뺐다.
`feed.json`에 기간별 수집 전량이 없어 `publish.py` 수정이 필요한데다,
"긁어온 것 중 쓸모 비율"이라 성격이 방금 걷어낸 분류 판정률과 같다.
RSS 소스 구성이 바뀌면 같이 움직이고 실무 판단으로 이어지지 않는다.
**다시 제안하지 말 것.**

세 창(7·30·120일) 모두 비율 편차가 작다(79 / 84 / 87%).
비율은 신호가 아니라 건수 옆 참고 수치다. 카드 본값은 건수이고 비율은 캡션에 둔다.

### 3번: 급상승 키워드 1~3위

`feed.momentum`에서 `delta > 0`이고 `TREND_CARD_EXCLUDE`에 없는 것 상위 3개다.

```
1위 리사이클    최근 4주 12건 / 직전  3건  (+9)
2위 제직        최근 4주  5건 / 직전  0건  (+5)
3위 스판덱스    최근 4주  4건 / 직전  0건  (+4)
```

카드 본값은 1위 태그 문자열이다. 2·3위는 `StatCard`의 `visual` 슬롯에 넣는다.
`visual`은 구분선 아래에 렌더되므로 순위 목록 자리로 맞다.
클릭은 1위 태그 필터로 건다. 2·3위 항목 자체를 각각 눌러 필터되게 하면 더 좋다.

제외 목록을 안 쓰면 1위가 `전시회`(14건 vs 직전 1건), 3위가 `방글라데시`가 된다.
이벤트·지역·기업 태그는 건수가 크게 튀어 소재 신호를 덮는다.
**카드 순위에서만** 뺀다. 태그 필터와 기사 목록에는 그대로 다 남는다.

### 4번: 저장된 기사

`teamStars`에서 기사 id를 `Set`으로 모아 센다. 같은 기사를 여러 명이 담아도 한 건이다.
이미 구현돼 있다(`savedStat`). 그대로 쓴다.

## 확정 스펙: HIT 처리

주목 기사(HIT ≥ 2)는 **카드에서 뺀다.** 대신 전체 기사 탭 정렬 칩 옆 문구로 살린다.

지금 그 자리에 이 문장이 있다.

> HIT는 같은 기사를 다룬 매체 수입니다. RSS는 조회수를 주지 않습니다.

여기에 건수를 붙여 진입점을 남긴다. 예: `최근 30일 2곳 이상이 같이 다룬 기사 11건.`
건수 부분을 눌러 `sort=hit`으로 가게 하면 좋다.

`hitCount` useMemo는 이 문구용으로 **남긴다.** 지우지 말 것.

## 확정 스펙: 하단 섹션 두 개 삭제

**태그 모멘텀**과 **수집 상태** 섹션을 지웠다. **완료됐다.** 되살리지 말 것.

같이 정리한 것.

- `Momentum` 컴포넌트 정의와 사용부. 하이라이트 탭은 `HighlightGrid`만 남는다.
- `Sparkline` import. 이 파일에서 쓰던 곳이 모멘텀 섹션뿐이었다.
- `status` 상태, `loadTrendStatus` 호출, `TrendStatus`·`RadioTower` import.
  `status`를 쓰던 곳이 수집 상태 섹션뿐이었다. `loadTrendFeed()` 단독 호출로 바꿨다.

수집 소스 현황은 1차 안에서 상단 카드를 빼고 수집 상태 섹션의 `actions` 배지로 옮겼는데,
그 섹션이 통째로 사라지면서 같이 없어졌다.

**부작용을 적어 둔다.** 막힌 소스가 화면에 드러나는 자리가 없어졌다.
현재 43곳 중 11곳이 비정상이고 이걸 화면에서는 알 수 없다.
`python run.py status` 또는 `doctor`로만 확인한다.
`public/data/trend/status.json`은 계속 생성되고 `loadTrendStatus`도 `src/data/trend.ts`에 남아 있다.
나중에 관리자 화면에 붙일 여지는 남겨 뒀다.

## 구현 메모

- `weekCount` / `weekDelta` useMemo는 `gateStat`으로 대체됐다. 1차 안의 "최근 7일 신규 + 증감" 카드는 사라졌다.
- `rising`은 `find` 단건에서 `filter(...).slice(0, 3)`으로 바뀌었다. 2·3위는 `StatCard`의 `visual` 슬롯에 목록으로 들어간다.
  목록 항목도 각각 눌러 태그 필터가 걸린다. 카드 자체의 `onClick`과 겹치므로 `event.stopPropagation()`을 넣었다.
- `hitCount`는 카드에서 빠지고 정렬 칩 옆 문구로 갔다. 건수 부분이 버튼이라 누르면 `sort=hit`이 된다.
- `freshTags`는 3번 카드 캡션 자리가 없어져 `info` 툴팁으로 내렸다.
  `publish.py`의 `fresh` 산출과 `TrendFeed.fresh` 타입은 그대로 유지한다.

## `fresh`에 관한 메모

`_fresh(rows, days=28)`는 "최근 28일에 나왔고 그 이전 보관분(120일 창)에는 없던 태그"를 센다.
`_momentum`이 `recent + prior < 3`이면 후보를 잘라내서, 이번에 처음 뜬 1~2건짜리 태그를
통째로 놓치기 때문에 따로 만들었다. 산출 형식은 `[{tag, n, first}]`, `n` 내림차순이다.

지금은 20개가 잡힌다. 수집기가 2026-08-31에 처음 돌아 비교할 과거분이 얇은 탓이다.
`방글라데시`, `제직`, `렌징`처럼 원래 있던 태그가 "처음 등장"으로 걸린다.
`n > 1` + 제외 목록을 적용하면 5개(`제직`, `스판덱스`, `BCI코튼`, `자카드`, `난연`)로 줄어든다.
이력이 4주쯤 쌓이면 독립 카드로 승격할지 다시 본다.

## 접은 후보: 바이어 언급

FABRIC 피드는 `config.feed_excluded_sources()`로 바이어·경쟁사 소스를 설계상 제외한다.
남는 건 섬유 전문지 기사뿐이고 거기엔 바이어 이름이 거의 안 나온다.
본문(`x` 필드)까지 넓혀 재매칭해도 204건 중 2건 그대로였다(`Target` 1, `신원` 1).
`buyers.json` 사전 문제가 아니라 구조 문제다. **다시 시도하지 말 것.**
바이어 동향은 MACRO 화면의 `entity_news`가 맡는다.
