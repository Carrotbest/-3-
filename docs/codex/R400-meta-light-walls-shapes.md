# R400 — META 7단계: 밝기, 섹션 격벽, 룸 형태, 고정 각도

상태: 미착수. R399 시공과 빌드 통과 직후다.

2026-11-09에 박향근이 R399 결과 화면을 보고 지시한 넷이다.

1. "전반적으로 너무 어둡다."
2. "섹션 격벽은 다시 있어야 할 것 같다."
3. "모든 룸을 네모로 하지 말고 다양한 공간과 구조로 만들어줘."
4. "3D 렌더링할때 어느 방향에서 보든 동일한 각도로 보여지게 해줘. 원근감은 필요 없다."

**2번은 R399의 결정을 뒤집는 것이다.** R399는 "섹션 경계벽을 세우지 않는다"였다. 그 조항은 폐기다. 아래 3절이 대체한다.

## 1. 고정 각도 — 먼저 한다

**원근 카메라로 바꾸지 마라. 이미 직교다.** 215줄이 `OrthographicCamera`다. 원근감은 처음부터 없었다. 박향근이 본 각도 변화는 `OrbitControls`가 세로 회전을 허용해서다. 223과 224가 극각을 0.25에서 1.337까지 열어 둬서 끌면 거의 위에서 보기부터 거의 옆에서 보기까지 바뀐다.

- 223과 224를 **같은 값 하나로 묶는다.** `const ISO_POLAR = Math.acos(1 / Math.sqrt(3))`(약 0.9553 라디안, 54.7356도)를 쓴다. 정아이소메트릭 각이다. `controls.minPolarAngle`과 `controls.maxPolarAngle`에 똑같이 넣는다.
- `camera.position`(216)을 그 각에 맞춘다. 타깃이 `(0, 0, -2)`(220)이므로 **타깃 기준 세 성분이 같아야** 한다. `camera.position.set(60, 60, 58)`이다.
- **가로 회전은 그대로 열어 둔다.** `minAzimuthAngle`과 `maxAzimuthAngle`을 건드리지 마라. 돌려도 기울기만 같으면 된다는 요구다. 방향 자체를 막으라는 말이 아니다.
- `minZoom`, `maxZoom`(225, 226)은 그대로다.

## 2. 밝기

원인이 다섯이다. **다섯을 다 고쳐야 한다.** 하나만 고치면 거의 안 달라진다.

### 2-1. HemisphereLight 바닥색이 거의 검정이다

228줄이 `new THREE.HemisphereLight(0x4a6fa5, 0x0d141f, theme.dark ? 0.6 : 0.95)`다. 두 번째 인자가 바닥에서 올라오는 빛인데 `#0d141f`다. **밝은 모드에서도 같은 값이다.** 위를 보는 면만 푸르게 밝고 옆면과 그늘은 전부 검정으로 끌려간다. 화면이 칙칙한 가장 큰 원인이다.

아래로 바꾼다.

```
const hemi = new THREE.HemisphereLight(
  theme.dark ? 0x5b7ba8 : 0xdce6f2,
  theme.dark ? 0x1a222e : 0xc8cfda,
  theme.dark ? 0.85 : 1.25,
)
```

### 2-2. 보조광이 파랗다

240줄이 `new THREE.DirectionalLight(0x5b9bff, 0.25)`다. 화면 전체에 푸른 기를 입힌다. 색을 `0xffffff`로 바꾸고 세기를 `theme.dark ? 0.3 : 0.4`로 올린다.

### 2-3. AmbientLight가 없다

재질이 전부 `MeshLambertMaterial`이라 정면광이 안 닿는 면은 hemi에만 기댄다. `sun` 뒤에 한 줄 더한다.

```
scene.add(new THREE.AmbientLight(0xffffff, theme.dark ? 0.25 : 0.45))
```

`sun` 세기(230)는 `theme.dark ? 0.8 : 1.15`로 올린다.

### 2-4. 안개가 화면 절반을 먹는다

213줄이 `new THREE.Fog(theme.bg, 70, 135)`다. 바닥이 104 × 72라 대각선이 127이다. 전체를 보는 화면이라 **늘 먼 구석 절반이 안개 속**이다.

- 밝은 모드는 안개를 쓰지 않는다. `scene.fog = null`.
- 어두운 모드만 `new THREE.Fog(theme.bg, 150, 320)`으로 멀리 민다.

`repaint`의 1697줄이 이미 `instanceof THREE.Fog` 가드를 달고 있어 `null`이어도 안전하다. 그 줄을 지우지 마라.

### 2-5. 바닥, 벽, 가구 색이 서로 너무 가깝다

밝은 모드에서 `--scene-floor` `#e4e9f0`, `--scene-wall` `#f2f5f9`, `--scene-desk` `#f0e7d6`가 전부 명도 90% 언저리다. 형태가 안 읽힌다. **바닥을 올리고 벽을 내려 둘을 뒤집는다.**

`src/index.css`의 **밝은 모드 블록만** 고친다.

| 토큰 | 지금 | 바꿀 값 |
|---|---|---|
| `--scene-floor` | `#e4e9f0` | `#f2f4f8` |
| `--scene-wall` | `#f2f5f9` | `#dfe5ee` |
| `--scene-metal` | `#aab6c6` | `#9aa7b8` |
| `--scene-dark` | `#6b7788` | `#5c6878` |

**어두운 모드 토큰은 손대지 마라.** 박향근이 아직 어두운 모드를 보지 않았다. 조명 수정만으로 어떻게 보이는지 먼저 확인할 자리다.

### 2-6. repaint 갱신

`repaint`의 1709, 1710이 세기만 갱신한다. hemi 색이 이제 모드마다 다르므로 `hemi.color`, `hemi.groundColor`, `fill.intensity`, 그리고 `scene.fog` 자체의 설정과 해제를 그 함수에서 함께 처리해라. **테마를 바꿨을 때 안개가 남거나 사라지지 않는 일이 없어야 한다.**

## 3. 섹션 격벽을 되살린다

R399는 "섹션끼리 맞닿는 자리가 없고 사이가 전부 주 통로라 격벽을 세우면 통로가 복도가 된다"는 이유로 뺐다. 화면을 보니 영역이 안 읽힌다는 것이 박향근 판단이다. **격벽을 주 통로 양옆 선에 세운다.**

### 선

네 선이다. 주 통로 사각형의 네 변이다.

| 선 | 좌표 | 구간 |
|---|---|---|
| 동서 통로 남쪽 | `z = -4` | `x` −51에서 51 |
| 동서 통로 북쪽 | `z = 6` | `x` −51에서 51 |
| 남북 통로 서쪽 | `x = -6` | `z` −37에서 33 |
| 남북 통로 동쪽 | `x = 4` | `z` −37에서 33 |

### 치수

- 높이 **2.2**, 두께 **0.2**. 재질은 `materials.wall`이다.
- 꼭대기에 그 쪽 섹션 구역 색 띠를 올린다. 폭 **0.06**, 높이 0.04, `zoneLineMaterials`를 쓴다. 한 선이 두 섹션을 가르므로 띠는 선 하나에 하나만, 그 선 **바깥쪽 섹션** 색으로 한다.
- **유리를 쓰지 마라.** 민면 하나다. 스캔라인도 네온도 없다.
- 2.2는 서면 너머가 보이고 앉으면 안 보이는 높이다. 방 벽(창고 3.0, 서버실 2.4)보다 낮아야 열린 평면이 유지된다. **올리지 마라.**

### 뚫는 자리

**좌표를 손으로 적지 마라. 계산해라.**

- 네 선이 서로 만나는 교차부 넷을 뚫는다. 뚫는 반폭은 통로 반폭에 2를 더한 값이다.
- `branchSegments`(1213~1223)를 읽어 **그 선을 가로지르는 가지 통로**를 찾는다. 가지 통로 하나가 선을 지나면 그 자리를 **폭 4**로 뚫는다. 가지 통로 폭이 2이므로 양옆에 1씩 여유를 둔 값이다.
- 뚫은 자리 양 끝에 반지름 0.14 원기둥 기둥을 높이 2.2로 세워 끝을 둥글게 마감한다.

격벽은 한 선이 여러 토막으로 끊긴 모양이 된다. **그것이 맞다.** 통째로 긴 벽 하나를 세우지 마라.

## 4. 룸 형태를 다양하게

### 데이터

`RoomCoordinate`(18~26)에 `shape` 필드를 더한다.

```
shape?: "rect" | "round" | "stadium" | "chamfer" | "ell"
```

**중심 좌표와 `w`, `d`는 바꾸지 마라.** 그 값은 그대로 그 영역의 바깥 테두리 상자다. 바뀌는 것은 그 상자 안에서 바닥 패치를 어떤 모양으로 깎느냐뿐이다.

| 값 | 모양 |
|---|---|
| `rect` | 지금 그대로 직사각형 |
| `round` | 네 모서리를 반지름 2로 둥글린다 |
| `stadium` | 짧은 변 두 쪽을 반원으로 닫는다 |
| `chamfer` | 마주 보는 두 모서리를 길이 4로 비스듬히 자른다 |
| `ell` | 한 모서리에서 가로 `w * 0.3`, 세로 `d * 0.4`짜리 직사각형을 판다 |

### 배정

| 경로 | shape | `ell`이면 파는 모서리 |
|---|---|---|
| `/` | `stadium` | |
| `/meta` | `round` | |
| `/development/workspace` | `ell` | 북서 |
| `/cost` | `round` | |
| `/request` | `chamfer` | |
| `/fabric-analysis` | `chamfer` | |
| `/warehouse` | `rect` | |
| `/ts` | `ell` | 북서 |
| `/study` | `rect` | |
| `/protocol` | `round` | |
| `/rdda` | `chamfer` | |
| `/trend/fabric` | `ell` | 남서 |
| `/trend/macro` | `rect` | |
| `/trend/portfolio` | `stadium` | |
| `/calendar` | `round` | |
| `/process-innovation` | `stadium` | |
| `/setting` | `rect` | |

`rect`가 다섯이다. 그 다섯은 세 면 벽이 있거나(창고, 서버실) 가구가 직각으로 줄 서야 하는 곳(서가, 스탠딩 데스크 2열)이다. **더 줄이지 마라.** 전부 곡선이면 그것도 단조롭다.

### 그리기

`THREE.Shape`로 모양을 만들고 `THREE.ShapeGeometry`로 바닥 패치를 깐다. `round`는 `quadraticCurveTo`, `stadium`은 `absarc`를 쓴다.

**테두리는 패치를 두 장 겹쳐 만든다.** 모양마다 둘레 선을 따로 계산하지 마라.

1. 아래 장: 그 모양 그대로, 크기 `w * 0.94` × `d * 0.94`, `y = 0.02`, 색은 구역 네온 색.
2. 위 장: 같은 모양을 둘레에서 **0.08만큼 안으로 줄인 것**, `y = 0.025`, 색은 지금 `roomFloorColor(room)`가 내는 값.

겹치면 둘레에 0.08짜리 색 테두리가 저절로 생기고 **모양이 어떻든 테두리가 그 모양을 따라간다.**

**`roomEdgeSides`(1103~1118)와 `addRoomEdge`(1120~1127)를 지워라.** R399의 "두 변만 두른다" 규칙은 폐기다. 직사각형이 아니면 어느 두 변인지 정의되지 않고, 모양 자체가 닫힌 상자로 보이는 것을 막아 준다. 열린 느낌은 3절의 격벽이 책임진다.

안으로 줄이는 계산은 모양마다 다르다. `round`와 `rect`와 `ell`은 각 변을 0.08씩 당기면 된다. `stadium`과 `chamfer`는 반지름과 자른 길이를 함께 줄여라. **`THREE.Shape`를 scale로 줄이지 마라.** 가로세로 비가 다르면 테두리 폭이 변마다 달라진다.

### 손대지 않는 것

- **히트박스는 사각 그대로다.** `hit.scale.set(room.w, 3.6, room.d)`를 모양에 맞추지 마라. 집기가 어려워진다.
- 바닥 글자, 행잉 사인, 시설 라벨 위치는 그대로다.
- **가구 좌표를 모양에 맞춰 옮기지 마라.** `ell`과 `chamfer`로 판 자리에 가구가 걸치면 **그 가구 하나만** 안쪽으로 당겨라. 전체 배치를 다시 짜지 마라.

## 하지 말 것

- 원근 카메라(`PerspectiveCamera`)로 바꾸지 마라.
- 가로 회전(azimuth)을 막지 마라.
- 영역 중심 좌표와 `w`, `d`를 바꾸지 마라.
- 어두운 모드 색 토큰을 바꾸지 마라.
- 네온, 광륜(`AdditiveBlending`), 유리 스캔라인, 바닥 격자, 통로 유도선을 다시 만들지 마라.
- 천장을 만들지 마라. 아이소메트릭이라 덮으면 안이 안 보인다.
- 후처리를 쓰지 마라.
- 담당자 집계나 팀 묶음을 만들지 마라. 예시 사람을 만들지 마라.
- 랜덤을 쓰지 마라. 좌표와 각도는 번호 해시로 정한다.
- 외부 3D 파일, 이미지, 폰트를 불러오지 마라.
- 한글을 영어로 바꾸지 마라. 파일은 UTF-8이다.
- 코드를 한 줄로 눌러 담지 마라. 커밋하거나 푸시하지 마라.

## 성능

격벽 토막과 모양 패치가 는다. 총 메시는 **3,500개 이하**를 지킨다. R399 직후가 1,759개다.

만든 geometry, material, texture는 정리 단계에서 전부 `dispose()` 해라. `ShapeGeometry`는 방마다 둘씩 새로 만드는 것이라 특히 빠뜨리기 쉽다.

## 검증

1. `npm run build` 한 번. 통과해야 한다. 1분쯤 걸린다.
2. `dist/assets`에서 `Meta` 청크 크기를 적어라. **작업 전 기준값이 `Meta` 10.92 kB, `OfficeScene` 545.99 kB다.** `Meta`가 12 kB를 넘으면 코드 분리가 깨진 것이다.
3. `git status --short`로 바뀐 파일이 `OfficeScene.tsx`와 `index.css` 둘뿐인지 확인해라.
4. 개발 서버를 띄우지 마라. 화면 확인은 박향근이 한다.

보고에는 고정한 극각 값, 조명 다섯 가지 수정 결과, 격벽이 몇 토막으로 끊겼는지, 모양별 영역 수, 총 메시 개수, 청크 크기, 판단이 필요했던 지점만 적어라. 코드를 붙이지 마라.

## 실제 적용 결과 (2026-11-09)

코덱스가 1절부터 3절까지와 4절의 모양 그리는 코드까지 하고 **사용량 한도에 걸려 끊겼다.** 끊긴 자리와 그 뒤 박향근 지시로 클로드가 마무리한 내용이 아래다.

### 코덱스가 못 끝낸 것

- `RoomCoordinate`에 `shape` 필드를 안 넣어 타입 오류 넷이 났다.
- 섹션 격벽 기둥의 `cylinder` 호출에 `parent` 인자가 빠져 오류 둘이 났다.
- `src/index.css` 밝은 모드 토큰 넷(2-5절)을 못 고쳤다.
- `ROOM_COORDINATES`에 `shape` 값을 못 넣었다. 그리는 코드만 있고 쓰는 데가 없었다.

### 지시서에서 달라진 것

- **`ell`을 쓰지 않는다.** 노치가 `w * 0.3 × d * 0.4`라 후보 방마다 가구와 정면으로 부딪친다. `/trend/fabric`은 노치 자리가 원단 전시 벽이고, `/development/workspace`는 캐비닛 줄과 화분, `/ts`와 `/request`는 책상 섬이 걸린다. 가구를 크게 옮겨야 해서 뺐다. `makeRoomShape`의 `ell` 분기는 남겨 뒀다. 나중에 가구 배치를 다시 짤 때 쓴다.
- **`chamfer` 자르는 길이를 4에서 2로 줄였다.** 4로 자르면 `/fabric-analysis` 캐비닛, `/protocol` 화이트보드, `/request` 캐비닛이 잘려 나간다. 2로 줄이고 모서리가 실제로 빈 세 방(`/rdda`, `/trend/macro`, `/calendar`)에만 배정했다.
- 모양 배정은 rect 5, round 6, chamfer 3, stadium 3이다.

### 방 크기를 줄였다

2026-11-09 박향근 추가 지시다. 가구가 실제로 차지하는 범위를 재서 여백 1.5를 더한 값으로 `w`, `d`를 줄였다. **중심 좌표는 그대로다.** 열 방이 줄었고 일곱 방은 이미 꽉 차서 그대로 뒀다. 상세는 `.codex-runs/R400-fix.txt`에 있다.

가구는 셋만 옮겼다. `/` 로비 `arcDesk` x 15.5에서 9.5로, `plantRow` x 2에서 0으로, `/meta` `bookshelf` z −5.4에서 −4.4로다.

### facilities.ts도 고쳤다

R400 본문은 이 파일을 건드리지 말라고 했다. 방 크기를 줄이는 것이 지시서에 없었기 때문이다. 방이 줄자 시설 넷이 방 밖으로 밀려나 고쳤다.
