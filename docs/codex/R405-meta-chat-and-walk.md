상태: 미착수.

2026-11-09 박향근 지시다. "실제 3D MMO RPG 게임처럼", "아바타들의 말풍선도 띄우고 실시간으로 채팅", "아바타의 상태나 기분 표시"다. 네 단계로 나눠 1단계와 2단계를 이번에 한다.

## 비용 전제 — 이 지시서의 뼈대다

**Firestore는 문서가 리스너에 전달될 때마다 읽기로 과금한다.** 아바타 위치를 초당 네 번 쓰면 6명 기준 하루 쓰기 69만 건, 읽기 345만 건이고 월 100달러쯤이다. 인원의 제곱으로 는다. 하트비트를 60초로 묶어 둔 이유(R320)가 이것이다.

그래서 2단계는 **목적지만 저장하고 걸어가는 중간 과정은 각자 브라우저가 그린다.** 쓰기는 사람이 바닥을 클릭할 때만 일어난다.

- **위치를 주기적으로 쓰지 마라.** `setInterval`로 좌표를 올리는 코드를 만들지 마라.
- **하트비트 60초를 줄이지 마라.**
- **보간은 각 클라이언트가 한다.** 목적지와 시작 시각만 공유한다.

## 1. presence 문서에 필드 셋을 더한다

`writePresence`가 `{ merge: true }`로 쓰므로 **기존 필드를 건드리지 않고 더할 수 있다.** 60초 하트비트는 지금 payload 그대로 두고, 새 필드는 바뀔 때만 따로 쓴다. 상태와 기분은 하루 몇 번이라 쓰기가 사실상 안 는다.

```
status?: "focus" | "meeting" | "away" | "busy"
mood?: "good" | "normal" | "tired" | "stuck"
spot?: { path: string; x: number; z: number; at: number }
```

- `spot.path`는 그 목적지가 어느 방 것인지다. **`presence.path`와 다르면 그 `spot`은 버린다.** 화면을 옮기면 목적지가 저절로 무효가 된다.
- `spot.x`와 `spot.z`는 **방 중심 기준 로컬 좌표**다. 월드 좌표를 쓰지 마라. 방 크기가 또 바뀌면 전부 어긋난다.
- `spot.at`은 `Date.now()`다. `serverTimestamp()`를 쓰지 마라. 걷기 시작 시각을 각 클라이언트가 바로 읽어야 한다.

새 함수 둘이다. 둘 다 실패해도 조용히 넘어간다. 접속 표시는 보조 기능이라는 기존 주석의 원칙 그대로다.

```
export async function writePresenceMood(status, mood): Promise<void>
export async function writePresenceSpot(path, x, z): Promise<void>
```

**`writePresenceSpot`에 1.5초 던지기 제한을 건다.** 마지막 쓰기 뒤 1.5초가 안 지났으면 건너뛴다. 같은 좌표면 쓰지 않는다(소수 둘째 자리까지 비교). 바닥을 연타해도 쓰기가 폭증하지 않는다.

`PresenceEntry`에 세 필드를 **선택으로** 더한다. 옛 문서에는 없다. `usePresencePeople`은 `?? undefined`로 읽는다.

## 2. 채팅

### 저장

새 컬렉션 `metaChat`이다. **`state/{key}` 청크 동기화에 넣지 마라.** `CACHE_KEYS`에 넣지 마라. 쌓이는 로그라 배열 통째 재업로드 구조에 두면 안 된다. `auditLog`와 같은 이유다.

문서 하나가 메시지 하나다.

```
{ uid, name, color, text, room, createdAt }
```

- `room`은 보낸 사람이 그때 있던 방 경로다. 빈 문자열이면 전체 대화다.
- `text`는 **200자까지**다. 넘으면 자른다.
- `createdAt`은 `serverTimestamp()`다.

### 읽기

`orderBy("createdAt", "desc")`에 `limit(50)`이다. 화면에서 뒤집어 보여 준다.

**옛 메시지를 지우는 코드를 만들지 마라.** 서버가 없어서 정리 작업을 돌릴 데가 없다. 쌓여도 읽기는 늘 50건이라 비용이 안 는다. 저장만 는다.

`/meta`를 열었을 때만 구독한다. 다른 화면에서는 구독하지 마라.

### 규칙

`firestore.rules`에 더한다.

```
match /metaChat/{id} {
  allow read: if isApproved();
  allow create: if isApproved() && request.auth.uid == request.resource.data.uid;
  allow update, delete: if isOwner();
}
```

**규칙은 수동 배포다.** `.github/workflows`에 firebase 배포가 없다. `firebase deploy --only firestore:rules`를 사람이 돌려야 한다. 안 올리면 맨 아래 `allow read, write: if false`에 걸려 채팅이 통째로 막힌다. COST SHEET가 그래서 한 달 넘게 저장에 실패했다(R340). **보고에 이 줄을 반드시 적어라.**

## 3. 말풍선

- 각 사람의 **가장 최근 메시지**를 아바타 위에 띄운다. 보낸 지 **8초**가 지나면 걷는다.
- 자리는 이름표 위 `y = 2.5`다. 이름표와 겹치면 안 된다.
- 기존 스프라이트 방식(`makeLabel`, `labelEntries`)을 그대로 쓴다. 카메라를 따라 도는 것이 맞다. 룸 깃발과 다르다.
- 캔버스는 흰 바탕에 그 사람 색 테두리 3px, 글자는 진한 회색이다. 꼬리를 아래에 붙인다.
- 한 줄에 **18자**까지 끊고 최대 두 줄이다. 넘치면 뒤를 `…`로 자른다.
- 전체 대화든 방 대화든 말풍선은 똑같이 뜬다.

## 4. 상태와 기분 표시

이름표 왼쪽에 작은 배지를 붙인다. 이름표 캔버스 안에 같이 그려라. 메시를 새로 만들지 마라.

| 상태 | 색 | 글자 |
|---|---|---|
| `focus` | `#2f9e8f` | 집중 |
| `meeting` | `#d8924a` | 회의 |
| `away` | `#9aa7b8` | 자리 비움 |
| `busy` | `#d4564f` | 바쁨 |

기분은 배지 오른쪽에 작은 얼굴이다. **이모지를 `fillText`로 쓰지 마라.** 폰트에 따라 안 나온다. `arc`와 `lineTo`로 그린다.

| 기분 | 그림 |
|---|---|
| `good` | 눈 둘, 웃는 호 |
| `normal` | 눈 둘, 가로 선 |
| `tired` | 눈이 가로 선 둘, 입은 작은 호를 뒤집음 |
| `stuck` | 눈 둘, 입은 작은 원 |

값이 없으면 배지를 그리지 않는다. 옛 문서에는 필드가 없다.

## 5. 클릭 이동

### 바닥을 고른다

지금 `pickables`에 방 히트박스와 시설만 있다. **걷기용 목록 `walkables`를 따로 만든다.** 방 바닥 패치와 카펫을 넣는다. 외벽, 격벽, 가구는 넣지 마라.

`handlePointerUp`의 판정 순서다.

1. `pickables`에 맞으면 지금 동작 그대로다(방 선택, 사람 선택, 시설).
2. 안 맞고 **방이 선택된 상태**이면 `walkables`를 쏜다. 맞으면 거기로 걷는다.
3. 둘 다 아니면 지금처럼 선택을 푼다.

**방을 고르지 않은 상태에서는 걷지 않는다.** 전체를 보는 중에 클릭하면 방 선택이 먼저다.

### 목적지를 다듬는다

- 맞은 점을 그 방의 **로컬 좌표**로 바꾼다.
- 방 테두리에서 **1.0 안쪽**으로 클램프한다. 벽에 붙지 않게 한다.
- **가구를 피해 돌아가지 않는다.** 직선으로 걷고 가구를 통과한다. 길찾기는 이번 범위가 아니다. 보고에 적어라.
- 자기 아바타만 움직인다. 남의 아바타를 옮길 수 없다.

### 걷기

- 속도는 **초당 2.2**다. 목적지에 닿으면 멈춘다.
- 걷는 동안 다리를 흔든다. `posePerson`의 앉기와 서기에 더해 **걷기 상태**를 만든다. 다리 회전은 `Math.sin(시각 * 7) * 0.5` 라디안이다.
- 몸이 **가는 방향을 본다.** `group.rotation.y`를 목적지 방향으로 돌린다.
- 멈추면 선 자세로 돌아간다. 책상 자리에 닿았는지 판정하지 마라. 앉기는 지금처럼 `syncPeople`이 정한다.
- 남의 아바타는 `spot.at`과 현재 시각으로 **어디까지 걸었을지 계산해서** 그 자리에 둔다. 중간에 들어온 사람도 자연스럽게 보인다.

### `syncPeople`과의 관계

지금 `syncPeople`이 방마다 사람을 자리에 배치한다. **`spot`이 있고 `spot.path`가 그 사람의 현재 `path`와 같으면 `spot`이 이긴다.** 없으면 지금 배치 그대로다.

## 6. 화면(`Meta.tsx`)

- 오른쪽 패널 아래에 **채팅 영역**을 붙인다. 입력 한 줄과 보내기, 그리고 최근 메시지 목록이다.
- 탭 둘이다. `전체`와 `이 방`이다. `이 방`은 방을 고른 상태에서만 열린다.
- 상단에 **상태와 기분 고르는 자리**를 둔다. 작은 드롭다운 둘이면 된다. 고르면 바로 저장한다. 저장 버튼을 만들지 마라.
- 읽기 권한만 있는 사람도 채팅은 보낼 수 있다. 채팅은 `CACHE_KEY_SCREENS` 대상이 아니다.

- 방 좌표, 외곽, 통로, 격벽, 카메라, 조명, 가구를 바꾸지 마라.
- 커서 위치나 셀 단위 작업 내용을 공유하지 마라. R320에서 일부러 뺐다. 화면 이름보다 잘게 드러내면 감시로 읽힌다.

- 랜덤을 쓰지 마라.
- 외부 3D 파일, 이미지, 폰트를 불러오지 마라.

## 성능

말풍선 스프라이트는 **사람 수만큼**이다. 6명이면 6개다. 메시가 거의 안 는다. **총 메시 3,500개 이하**를 지킨다. 작업 전이 1,410개다.

말풍선 캔버스는 메시지가 바뀔 때만 다시 그린다. 매 프레임 그리지 마라.

## 실제 적용 결과 (2026-11-09)

코덱스 사용량 한도가 오후 2시까지라 박향근 판단으로 클로드가 시공했다.

### 배포 전에 반드시 할 것

**`firestore.rules`를 수동 배포해야 채팅이 돈다.**

```
firebase deploy --only firestore:rules
```

`.github/workflows`에 firebase 배포가 없다. 안 올리면 맨 아래 `allow read, write: if false`에 걸려 채팅이 통째로 막힌다. COST SHEET가 이것 하나로 2026-10-01 도입부터 한 달 넘게 저장에 실패했다(R340).

### 지시서에서 달라진 것

- **걷기는 새로 짜지 않았다.** `tick`에 이미 `visual.target`으로 걸어가는 처리와 다리 흔들기, 몸 돌리기가 있었다. `syncPeople`이 `spot`을 목적지로 쓰게만 바꿨다. 속도는 기존 5.2를 그대로 뒀다. 지시서의 2.2는 느리다.
- **바닥 전용 raycast 목록(`walkables`)을 만들지 않았다.** 방 히트박스가 방 전체를 덮고 있어 빈 곳을 클릭해도 그것이 먼저 맞는다. 대신 `y = 0` 수평면(`groundPlane`)에 광선을 쏴 바닥 좌표를 바로 얻는다. 히트박스 윗면(y 3.6)에 맞은 점을 쓰면 비스듬한 카메라에서 5미터쯤 어긋난다.
- **선택 해제 방법이 바뀌었다.** 전에는 고른 방을 다시 누르면 풀렸다. 지금은 그것이 걷기 명령이다. 해제는 방 **바깥**을 누르거나 Esc다.
- **상태와 기분은 이름표 캔버스 안에 그렸다.** 메시를 새로 만들지 않았다. `drawLabel`에 `badgeColor`와 `mood` 옵션을 더했고 기분 얼굴은 `arc`와 `lineTo`로 그린다. 이모지를 쓰지 않았다.
- **`Meta` 청크가 15.97 kB다.** 지시서에 적은 14 kB를 넘었다. 다만 **코드 분리는 안 깨졌다.** `OfficeScene`이 568.92 kB로 따로 서 있다. 늘어난 5 kB는 채팅 UI와 상태 고르는 자리다.
