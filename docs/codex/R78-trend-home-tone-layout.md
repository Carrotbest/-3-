# 설계 원칙: 어디까지 HOME처럼 만들 것인가

먼저 정하고 들어간다. 이걸 안 정하면 화면이 예뻐지고 못 쓰게 된다.

HOME은 착지 화면이다. 숫자가 적고 여백이 넓다. 그래서 글래스와 블러, 자석 호버,
3D 틸트가 값을 한다. 시선을 잡아 두는 게 그 화면의 일이다.

TREND는 훑는 화면이다. 기사 200건과 지표 수십 개를 눈으로 빨리 지나가야 한다.
반투명 표면과 블러를 목록 전체에 깔면 대비가 떨어져 읽는 속도가 느려진다.
호버마다 카드가 기울면 스캔이 방해된다.

**그래서 층을 나눈다.**

| 층 | 성격 | 적용 |
|---|---|---|
| 요약층 (히어로, KPI, 핫 키워드) | 눈길을 끄는 게 일 | HOME 톤 전면 적용. 글래스, 모션, 큰 수치, 썸네일 |
| 작업층 (필터, 기사 목록, 지표 타일) | 읽는 게 일 | 현재 평면 카드 유지. 타이포와 간격 리듬만 HOME에 맞춤 |

이 원칙은 문서 전체에 걸린다. 판단이 갈리면 "이 요소는 끌기 위한 것인가 읽기 위한 것인가"로 되돌아온다.

# HOME에서 가져올 것

`Home.tsx`에 이미 있는 것들이다. 새로 만들지 말고 그대로 쓴다.

## 표면 상수

`Home.tsx` 55~57행의 세 상수를 공용 파일로 옮긴다.
`src/lib/home-surface.ts`를 새로 만들고 거기서 `export`한 뒤 세 화면이 함께 import한다.
복사해서 세 벌로 두면 나중에 색을 못 맞춘다.

```
HOME_GLASS_SURFACE   rounded-[12px] border-white/60 bg-white/46 backdrop-blur-md + 2단 그림자
HOME_GLASS_STATIC    호버해도 그림자 안 변함. 큰 컨테이너용
HOME_GLASS_HOVER     테두리와 그림자가 살짝 뜸. 누를 수 있는 카드용
```

## 반복되는 조각

- **상단 하이라이트 선.** `absolute inset-x-5 top-0 h-px bg-white/80`.
  글래스 카드 상단에 유리 모서리 느낌을 준다. 카드마다 하나씩 넣는다
- **아이콘 칩.** `size-9 rounded-[9px] border border-white/70`,
  배경은 `color-mix(in oklab, {accent} 11%, var(--card))`, 글자색은 accent
- **출처 배지.** 우상단. `border-white/65 bg-white/34 text-[10px]`.
  HOME은 여기에 `DD 전체현황`을 넣는다. TREND는 `RSS 43곳` / `SEC·FRED·World Bank`를 넣는다
- **accent 글로우.** `absolute -right-12 -top-14 size-32 rounded-full opacity-[0.055] blur-2xl`.
  호버 시 `scale-110`, `opacity-[0.11]`
- **큰 수치.** `text-4xl font-semibold tracking-[-0.035em]` + `NumberTicker`,
  단위는 뒤에 작게 `text-xs font-normal`
- **필 토글.** `rounded-full border-white/80 bg-white/60 p-1` 안에 칩.
  선택된 것은 `bg-white shadow`. HOME의 RDDA 기간 선택이 이 모양이다

## 모션

전부 `src/components/motion/`에 있다.

- `Reveal` — 진입. 카드마다 `delay`를 75ms씩 계단으로
- `Magnetic` — `strength={5} lift={4} tilt={1.2}`. KPI 카드용. 약하게
- `Tilt3D` — `max={10} lift={12}`. 썸네일 카드용
- `NumberTicker` — 수치. `startOnView`를 쓴다

**작업층에는 `Magnetic`과 `Tilt3D`를 쓰지 않는다.** 목록 항목이 기울면 읽기 어렵다.

## 썸네일 카드 패턴

`Home.tsx`의 `DemoTrendGrid`(709행)가 원형이다. 구성은 이렇다.

- 16:9 비율, 배경은 `bg-gradient-to-br from-[var(--chart-3)] via-[var(--chart-2)] to-[var(--chart-1)]`
- 이미지는 `object-cover`, 호버 시 `scale-110`
- 이미지가 없으면 그라디언트 위에 아이콘
- 좌상단 `Badge`로 분류
- 제목 `line-clamp-2 text-sm leading-6`
- 하단 `날짜 · 출처` 를 `text-xs text-[var(--muted-foreground)]`

FABRIC TREND 기사에 그대로 맞는다. 실측 이미지 보유율이 204건 중 134건(66%)이라
빈 칸이 많이 생기지 않는다. 없는 건 그라디언트로 떨어지므로 깨져 보이지 않는다.

# FABRIC TREND 레이아웃

위에서 아래로 이 순서다. `<section className="min-w-0 space-y-8">`로 감싼다.
HOME이 `space-y-8`을 쓴다. 간격 리듬을 맞추는 게 톤을 맞추는 일의 절반이다.

## 1. 히어로 요약 (신설)

HOME의 `Overall status` 카드에 대응한다. 폭 전체를 쓰는 글래스 카드 하나다.

왼쪽에 대형 수치. `최근 30일 소재 기사 132건`.
오른쪽에 분류 분포를 가로 스택 막대 하나로 넣는다. MATERIAL 50, FABRIC 43, CHEMICAL 15, YARN 2 식이다.
막대 조각을 누르면 그 분류로 필터가 걸린다.

**지금 아래쪽에 따로 있는 `최근 30일 기사 분류` SectionCard를 여기로 흡수하고 원래 자리에서 지운다.**
같은 정보가 두 번 나올 이유가 없고, 히어로에 실체가 있어야 장식이 아니게 된다.

R77에서 그 SectionCard의 부제를 지우기로 했는데, R78에서는 섹션 자체가 사라진다.
R77을 먼저 하고 R78에서 걷어내는 순서가 맞다.

## 2. KPI 3-up

`grid gap-5 sm:grid-cols-3`. HOME과 같은 격자다. 지금은 4-up인데 3-up으로 줄인다.

| 카드 | 내용 |
|---|---|
| 최근 30일 소재 기사 | 132. accent `var(--gradient-1)` |
| 최근 7일 소재 기사 | 83. accent `var(--chart-2)` |
| 저장된 기사 | 팀 별표 수. accent `var(--chart-4)` |

**급상승 키워드는 KPI에서 빼고 3번으로 승격한다.** 좁은 칸에 썸네일 3개를 넣으려니
클립이 28px까지 작아진다. 그림이 그 크기면 없느니만 못하다.

카드 내부는 HOME의 `KpiCard`(59행)를 그대로 따른다. 아이콘 칩, 라벨, 큰 수치,
`rangeLabel`에 해당하는 줄, 캡션 순서다. R77에서 만든 `applyCardFilter` 호출은 유지한다.

`KpiCard`를 `Home.tsx`에서 공용으로 빼는 것도 방법이지만, HOME 전용 소품이 섞여 있다
(`DD 전체현황` 배지, `onCalendarClick`). **복사해서 TREND용으로 만들되 표면 상수만 공유한다.**
공용화는 세 번째 사용처가 생길 때 한다.

## 3. 핫 키워드 스트립 (신설, R77의 핫클립을 승격)

`grid gap-5 sm:grid-cols-3`. 급상승 1·2·3위를 `DemoTrendGrid` 패턴의 카드로 만든다.

카드 하나의 구성이다.

- 16:9 썸네일. 그 태그를 단 기사 중 이미지가 있는 가장 최근 기사의 `i`
- 좌상단 배지에 순위. `1`, `2`, `3`
- 우상단에 증감. `+9`
- 제목 자리에 태그명을 크게. `리사이클`
- 하단에 `최근 4주 12건 · 직전 3건`

누르면 `applyCardFilter({ range: 30, tag })`. R77에서 만든 헬퍼를 그대로 쓴다.

`Tilt3D`로 감싼다. 이 스트립은 요약층이라 모션을 써도 된다.

실측 이미지 보유율이 좋다. 리사이클 15건 중 11건, 제직 5건 중 5건, 스판덱스 4건 중 4건이다.

## 4. 탭

`하이라이트` / `전체 기사` / `저장 기사` 유지. 탭 바를 HOME의 필 토글 모양으로 바꾼다.
`rounded-full border-white/80 bg-white/60 p-1`, 선택된 칩은 `bg-white shadow`.

## 5. 하이라이트 탭 = 썸네일 그리드

지금 `HighlightGrid`를 `DemoTrendGrid` 패턴으로 다시 만든다.
`grid gap-5 sm:grid-cols-2 xl:grid-cols-4`. `Reveal` delay를 `index * 75`로.

이 탭이 "톤앤매너 맞춤"의 핵심 수확이다. 지금은 목록에 가까워 HOME과 이질적이다.

HIT 2 이상인 기사는 배지를 하나 더 붙인다. 여러 매체가 같이 다뤘다는 신호다.

## 6. 전체 기사 탭 = 목록 유지

**여기는 바꾸지 않는다.** 200건을 훑는 자리다. 썸네일 격자로 만들면 스크롤이 네 배가 된다.
필터 패널과 기사 행은 지금의 평면 카드를 그대로 둔다.

다만 두 가지만 맞춘다.

- 필터 패널 바깥 껍데기만 글래스로. 내부 칩과 목록은 그대로
- 기간·정렬 칩을 HOME의 필 토글 모양으로

## 7. 저장 기사 탭

`SavedList` 유지. 카드 껍데기만 글래스로 맞춘다.

# MACRO TREND 레이아웃

## 썸네일이 없다는 점을 먼저 인정한다

FABRIC은 기사 이미지가 있다. MACRO는 없다. 지표와 재무 수치뿐이다.
**MACRO의 시각 앵커는 사진이 아니라 차트다.** 스파크라인과 면적 그래프가 썸네일 역할을 한다.

그래서 FABRIC의 썸네일 그리드를 그대로 옮기지 않는다. 억지로 이미지를 넣을 자리가 없다.

## 1. 히어로 요약 (신설)

원가 신호 둘을 크게 잡는다. **면화 A Index**와 **유가(Brent)**다.
이 둘이 원단 원가의 선행 지표라서 팀이 가장 먼저 보는 숫자다.

글래스 와이드 카드 안에 좌우 2분할. 각각 큰 수치와 전년 대비, 그리고 넓은 면적 그래프.
R76에서 축을 좁히고 면적 채움을 넣기로 했으므로 그 결과가 여기서 가장 잘 보인다.

## 2. 지표 타일 6개

`grid gap-5 md:grid-cols-2 xl:grid-cols-3` 유지. 껍데기를 글래스로 바꾸고
R76의 축·색·모션 개선을 적용한다.

히어로로 올린 두 개(면화, 유가)를 여기서 뺄지는 판단이 필요하다.
**빼지 않는 쪽을 권한다.** 6개가 나란히 있어야 서로 비교가 되고, 히어로는 강조지 이동이 아니다.
대신 히어로에 올라간 두 타일에는 작은 표식을 넣어 중복이 아니라 강조임을 알린다.

## 3. 바이어 모니터링

좌측 목록 + 우측 상세 구조를 유지한다. 이건 잘 작동하는 구조다.

- 좌측 목록 행에 **스파크라인을 하나씩 넣는다.** 지금은 이름과 증감률만 있어 밋밋하다.
  매출 추이 12분기를 얇은 선으로 그리면 목록 자체가 비교 화면이 된다
- 우측 상세의 세 타일(매출·영업이익·재고)은 글래스로
- R76에서 5곳 미수집이 해결되면 14곳 전부 스파크라인이 찬다

## 4. 최신 동향 기사

우측 상세 하단의 바이어별 기사 목록은 유지한다.
FABRIC의 썸네일 카드 패턴을 여기 쓰지 않는다. 이 목록은 보조 정보고 3~5건뿐이다.

# 다크 모드 주의

`HOME_GLASS_SURFACE`가 `border-white/60 bg-white/46`처럼 흰색을 직접 쓴다.
HOME은 이 상태로 이미 배포돼 있으니 같은 값을 쓰면 동작은 한다.

다만 TREND 화면을 어두운 배경에서 보는 경우가 있으면 유리 표면이 뿌옇게 뜬다.
**작업 범위를 넓히지 말고**, HOME과 동일하게 두되 눈에 띄게 어색하면 사용자에게 알린다.
전역 토큰으로 바꾸는 건 HOME까지 함께 봐야 하는 별도 작업이다.

# 검증

```
npm run build
```

`preview_start`로 `fabric-rnd-vite`(5175)를 띄우고 확인한다.
Python 정적 서버는 TSX를 깨뜨리므로 쓰지 않는다. 로그인이 필요한 화면이다.

1. HOME과 TREND를 번갈아 보며 카드 모서리 반경, 그림자 세기, 간격이 같은 계열인지
2. 히어로 막대를 눌렀을 때 분류 필터가 걸리는지
3. 핫 키워드 카드를 눌렀을 때 R77의 숫자 정합이 그대로 유지되는지
4. 하이라이트 탭에서 이미지 없는 기사가 그라디언트로 떨어지는지
5. 전체 기사 탭 목록이 여전히 평면이고 스크롤이 빠른지
6. `prefers-reduced-motion`을 켠 상태에서 모션이 죽는지
7. 좁은 폭에서 히어로 좌우 분할이 세로로 접히는지

## 하지 말 것

- 기사 목록 행에 글래스나 3D 틸트를 넣는 것. 읽기가 나빠진다
- `Home.tsx`를 고치는 것. 이 작업의 대상이 아니다
- 수집기와 JSON 구조를 바꾸는 것. 화면 작업이다
- 히어로를 만들면서 기존 정보를 지우는 것.
  `최근 30일 기사 분류` 섹션만 흡수 대상이고 나머지는 자리만 옮긴다
