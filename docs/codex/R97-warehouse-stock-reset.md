# R97 — 입고 대기로 되돌릴 때 재고 초기화, 재고 직접 수정, 숨김 기록 정리

상태: 구현 완료(클로드 직접 시공, Codex 한도 소진). 화면 확인만 남음.

## 배경

입고 대기 원단을 실수로 창고 보관으로 옮겼다가 되돌렸더니 재고 숫자와 출고 이력이 그대로 남았다. 되돌린 행은 아직 입고한 적이 없는 상태인데 재고가 붙어 있다.

확인한 원인은 두 군데다.

1. `applyFabricAction`(`src/store/useAppStore.ts`)이 UNRECEIVE에서 `storageNo`만 지우고 `yds`는 이전 값을 그대로 물려줬다.
2. `buildFabricLedger`의 이벤트 집계가 그 원단의 모든 OUTBOUND를 무조건 합산했다. 되돌림 이전의 출고까지 계속 잔량에서 빠졌다.

곁다리로 하나 더 있었다. 이벤트 배열은 최신이 앞인데 집계 루프가 그 순서대로 돌면서 `CONFIRM`을 지웠다. 그래서 되돌린 뒤 다시 입고해 실물 확인을 해도 확인 표시가 지워졌다.

## 조치

### 1. 되돌리면 재고 기간이 끝난다

- `applyFabricAction`: UNRECEIVE면 override의 `yds`를 비운다.
- `buildFabricLedger`: 이벤트를 **오래된 것부터** 훑고, `UNRECEIVE`를 만나면 그 key의 출고 목록과 입고일을 비운다. 출고 날짜는 사용자가 과거로 고를 수 있어 `occurredAt`이 아니라 기록 순서를 기준으로 삼는다.
- 이벤트 자체는 지우지 않는다. 원단 상세의 이력에는 지난 입고와 출고가 그대로 남는다.
- UNRECEIVE 확인 문구도 실제 동작에 맞게 고쳤다.

### 2. 재고 셀 더블클릭으로 수량 수정

- 창고 화면 `재고` 셀을 더블클릭하면 "보유 재고 수정"이 열린다(이력 탭 제외). 한 번 클릭은 종전대로 반출 이력이다.
- 다이얼로그에 현재 전체 수량, 출고 합계, 현재 잔량을 함께 보여준다.
- 전체 수량과 잔량 둘 다 입력할 수 있고, 한쪽을 고치면 다른 쪽이 따라 바뀐다. 잔량 = 전체 − 출고 합계 관계를 유지한다. 출고 이력은 건드리지 않는다.

### 3. DD 원본을 지우면 숨김 기록도 지운다

`deleteDevelopmentRecord`가 레코드만 지우고 `REMOVED` 오버라이드를 남겼다. 원장 key가 내용 기반(R96)이라, 같은 내용으로 다시 등록하면 그 오버라이드가 다시 붙어 숨은 채로 나타난다.

- DD 레코드를 지울 때 그 행의 원장 항목이 `REMOVED`면 오버라이드와 `REMOVE` 이벤트를 함께 지운다.
- 채번·재고·출고 기록(다른 상태의 오버라이드)은 건드리지 않는다.
- 숨김 항목을 찾기 위해 `buildFabricLedger`에 `options.includeRemoved`를 넣었다. 기본값은 종전과 같다.

## 검증

`npm run build` 통과. 원장 집계는 실제 파일을 트랜스파일해 11가지를 확인했다.

| 확인 | 결과 |
|---|---|
| 되돌린 뒤 출고 합계 0, 재고 미입력, 입고일 없음 | 통과 |
| 되돌린 뒤 재입고하면 새 출고만 합산 | 통과 |
| 되돌린 뒤 재입고 후 실물 확인이 남는다 | 통과 |
| 확인한 뒤 되돌리면 확인 해제 | 통과 |
| 되돌림이 없으면 종전대로 합산 | 통과 |

## 남은 것

숨긴 행을 다시 보거나 되살리는 화면은 없다. `includeRemoved`는 넣어 뒀으니 필요하면 목록 하나만 붙이면 된다.
