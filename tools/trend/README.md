# TREND REPORT 수집기

웹 대시보드의 FABRIC TREND와 MACRO TREND 두 화면에 들어갈 자료를 자동으로 모읍니다.
AI를 호출하지 않습니다. 사전과 가중치, 공개 API만 씁니다. 토큰 비용이 0원입니다.

수집은 GitHub Actions가 매일 돌립니다. 사내 PC와 작업 스케줄러가 필요 없습니다.

---

## 두 갈래

**1. 소재 기사 (FABRIC TREND)**

섬유 전문지 24곳의 RSS를 받습니다. 소재 게이트(MATERIAL, YARN, FABRIC, CHEMICAL)를 먼저 보고,
통과하지 못한 기사 중 유통·브랜드 사업 기사는 리테일 게이트(RETAIL)로 따로 남깁니다.

제목은 한국어로 바꿔서 보여 줍니다. 용어는 원문 표기를 그대로 둡니다. 원문 제목과 요약은 아래에 같이 붙습니다.

**2. 바이어 동향과 거시 지표 (MACRO TREND)**

바이어 실적은 미국 SEC 공시에서 받습니다. 분기 매출, 영업이익, 분기말 재고를 같이 봅니다.
재고가 쌓이는 국면에서는 신규 개발 발주가 먼저 줄기 때문입니다.
바이어별 소싱과 실적 기사도 따로 받아서 실적 옆에 붙입니다.

정부 통계는 World Bank 원자재 가격과 미국 Census 수입 통계입니다.
면화 A Index와 유가가 원가의 선행 지표입니다.

## 실행

```
pip install -r requirements.txt
python run.py doctor       사내망 점검. 이것부터 돌립니다
python run.py collect      기사 수집 후 웹 JSON 재생성
python run.py kpi          지표 수집 후 웹 JSON 재생성
```

| 명령 | 하는 일 | 주기 |
|---|---|---|
| `collect` | 기사 수집 후 웹 JSON 재생성 | 매일 |
| `kpi` | 바이어와 정부 지표 수집 후 재생성 | 주 1회 |
| `rescore` | 재수집 없이 사전만 다시 적용 | 사전 수정 후 |
| `publish` | 수집 없이 웹 JSON만 재생성 | 수시 |
| `status` | 소스 상태와 보관 건수 | 수시 |
| `doctor` | 소스별 접근 가능 여부 점검 | 망 바뀔 때 |
| `translate` | 비어 있는 한국어 제목만 채움 | 번역 실패 후 재시도 |
| `why "검색어"` | 왜 채택됐는지 점수 근거 확인 | 사전 튜닝용 |

산출물은 세 개입니다. `public/data/trend/feed.json`, `kpi.json`, `status.json`입니다.
React 화면은 이 세 파일만 읽습니다. 서버도 DB도 없습니다.

## 자동 실행

`.github/workflows/trend.yml`이 전부 합니다.

- 매일 06:00 KST에 기사를 수집합니다.
- 매주 화요일 06:30 KST에 지표를 수집합니다. 월간 지표를 매일 긁을 이유가 없습니다.
- 결과를 저장소에 커밋합니다.
- 커밋이 생기면 Pages 배포를 직접 호출합니다.

마지막 항목이 중요합니다. GITHUB_TOKEN이 만든 push는 다른 워크플로를 깨우지 않습니다.
그래서 `deploy.yml`에 `workflow_call`을 열어 두고 트렌드 워크플로가 직접 부릅니다.

수동으로 한 번 돌리려면 Actions 탭에서 Trend collect를 실행합니다. KPI 체크박스를 켜면 지표도 같이 받습니다.

### 저장소 Secrets

| 이름 | 용도 | 없으면 |
|---|---|---|
| `SEC_CONTACT` | SEC가 요구하는 연락처. 회사 메일 주소를 넣습니다 | 바이어 실적이 안 들어옵니다 |
| `CENSUS_API_KEY` | 미국 수입 통계. https://api.census.gov/data/key_signup.html 에서 즉시 발급 | 미국 수입액과 국가별 점유율이 안 들어옵니다 |
| `FRED_API_KEY` | USD/KRW, 미국 의류 CPI, 의류점 재고 | 환율은 Frankfurter, CPI는 BLS로 대체하고 재고만 빠집니다 |
| `MT_CONTACT` | 번역 예비 엔드포인트(MyMemory)의 무료 한도를 하루 5천 자에서 5만 자로 올립니다. 선택 사항 | 주 엔드포인트가 막힌 날 번역이 일부 빠집니다 |

키가 없어도 기사 수집은 정상 동작하며 해당 지표만 예비 경로를 쓰거나 조용히 건너뜁니다.
개인 메일을 코드나 설정 파일에 넣지 마십시오. Secrets로만 주입합니다.

## 설정 파일

전부 `config/` 아래에 있습니다. 코드를 고치지 않고 이 파일만 고칩니다.

**`sources.json`** 수집 소스 목록입니다. `via`가 세 가지입니다.
`direct`는 RSS 주소를 그대로 씁니다. `googlenews`는 직접 요청이 막힌 매체를 도메인으로 우회합니다.
`googlenews_query`는 매체가 아니라 주제로 긁습니다.

**`relevance.json`** 관련도 점수 사전입니다. 이 파일이 화면 품질을 결정합니다.
`gates.material`은 7점, `gates.retail`은 6점 이상이면 화면에 나갑니다.
`source_bias`는 매체 성격에 따른 기본 점수입니다. 소재 전문지는 올리고 패션지는 내립니다.
`signals`는 어휘 묶음별 가중치입니다. `requires`가 있으면 그 신호가 있을 때만 셉니다.

**`categories.json`** MATERIAL, YARN, FABRIC, CHEMICAL, RETAIL 판정 사전입니다.
매칭 개수가 가장 많은 쪽으로 정합니다. 동점이면 `_order`가 앞선 쪽입니다.

**`tags.json`** 태그 사전 73개입니다. 팀 기술 라이브러리 태그 체계가 확정되면 통째로 교체합니다.

**`buyers.json`** 바이어 목록입니다. `cik`가 있으면 SEC에서 자동으로 받습니다.

**`glossary.json`** 제목을 한국어로 바꿀 때 원문 표기를 유지할 용어입니다.
`tags.json`의 영문 매칭어 중 고유명사와 약어는 자동으로 합쳐지므로 중복해서 넣지 않아도 됩니다.

**`kpi_manual.csv`** 자동 수집이 안 되는 지표를 손으로 넣는 자리입니다.
`metric,period,value` 세 컬럼입니다. 정의는 `kpi_manual.json`에 있습니다.

## 사전 튜닝 방법

이게 앞으로 손이 가는 유일한 작업입니다. 재수집은 필요 없습니다.

수집한 기사는 점수가 낮아도 지우지 않습니다. `relevant`를 false로만 둡니다.
사전을 고치고 `rescore`만 돌리면 보관분 전체를 다시 판정합니다.

```
python run.py why "니트"        점수 근거를 봅니다
python run.py rescore           사전 수정 후 다시 판정합니다
```

`why`는 어떤 어휘 때문에 몇 점이 붙었는지 신호별로 보여 줍니다.
안 나와야 할 기사가 나오면 그 기사에 걸린 어휘를 `noise_` 신호에 추가합니다.
나와야 할 기사가 빠지면 `core`나 `innovation`에 어휘를 추가합니다.

## HIT 정렬

RSS는 조회수를 주지 않습니다. 그래서 HIT는 조회수가 아닙니다.
**같은 기사를 몇 개 매체가 다뤘는지**를 셉니다. 우리가 쓸 수 있는 유일한 주목도 신호입니다.

제목에서 매체명 접미사를 떼고 영숫자와 한글만 남긴 뒤 해시를 만듭니다.
그 해시가 같으면 같은 기사로 봅니다. 본문은 먼저 들어온 쪽을 남기고 매체 수만 올립니다.
화면에서 HIT 2 이상이면 제목 옆에 숫자가 붙고, 어느 매체들이 다뤘는지 마우스를 올리면 보입니다.

정렬은 세 가지입니다. 최신순, HIT순, 관련도순입니다.

## 제목 한국어 변환

무료 기계번역 엔드포인트 두 곳을 순서대로 씁니다. LLM이 아닙니다. 토큰 비용이 없습니다.
`clients5.google.com`을 먼저 부르고 막히면 MyMemory로 넘어갑니다. 둘 다 실패하면 원문 제목을 그대로 둡니다.

한 번 번역한 제목은 보관소에 남습니다. 같은 기사를 다시 부르지 않습니다.
하루 호출량은 신규 기사 수만큼입니다.

**용어는 번역하지 않습니다.** TENCEL, Lyocell, r-PET, GRS 같은 말을 한글로 풀면 오히려 못 읽습니다.
번역 전에 `qqaqq` 형태의 자리표로 바꿔 두고 번역 후 원문 표기로 되돌립니다.
번역기가 이 토큰을 건드리지 않고 어순만 옮기는 것을 실측으로 확인했습니다.

용어를 늘리거나 줄이려면 `config/glossary.json`을 고칩니다.
이미 번역된 제목은 그대로 남으므로, 전체에 반영하려면 보관 파일의 `title_ko`를 비우고 `translate`를 다시 돌립니다.

원문 제목은 화면에서 번역 제목 바로 아래에 작게 남습니다. 요약은 원문 그대로입니다.

## 기업 동향

`sources.json`에서 `kind`가 `buyer`인 소스는 기업 동향 전용입니다.
이 기사들은 점수와 관계없이 FABRIC TREND에서 제외되고 MACRO TREND 기업 카드에만 붙습니다.

기사와 바이어를 잇는 매칭어는 `buyers.json`의 `alias`입니다.
Target과 Amazon처럼 보통명사와 겹치는 이름은 `ambiguous`로 표시해서 유통 맥락이 함께 있을 때만 연결합니다.
표시하지 않으면 "targets protective fibres" 같은 제목이 Target 기사로 잡힙니다.

## 확인된 결과 (2026-08-31 기준)

소재 소스 24곳과 바이어 소스 10곳 전부에서 수집이 됐습니다.
소재 기사는 628건이 들어와 관련도 판정 후 174건이 남았습니다. 분류 판정률은 84%입니다.
제목 한국어 변환은 전건 성공했습니다.

지표는 29개가 붙었습니다. 바이어 9개사의 분기 매출, 영업이익, 재고가 27개,
면화 A Index와 유가가 2개입니다. Target 회계연도 2025년 4개 분기 합계가 10-K 매출과 정확히 일치합니다.

## 알아 둘 것

**Google News는 기간을 안 걸면 2001년 기사까지 올려줍니다.** 검색어에 `when:45d`를 붙여 막았습니다.
그래도 새는 것이 있어서 540일보다 오래된 기사는 저장 단계에서 버립니다.

**분기 매출은 공시에 그대로 없습니다.** 10-Q는 3개월 구간과 누계 구간을 같이 싣습니다.
4분기는 3개월 구간이 아예 없습니다. 연간에서 1분기부터 3분기를 빼서 만듭니다.

**소매업 회계연도는 달력과 어긋납니다.** Walmart FY2027 Q2는 달력 2026년 5월부터 7월입니다.
화면에 회계분기 라벨과 실제 종료일을 같이 표시합니다. 노후 판정도 실제 종료일로 합니다.

**World Bank 파일 주소에는 업로드 해시가 박혀 있습니다.** 고정 주소로 긁으면 옛 스냅샷이 잡힙니다.
실제로 2021년 경로 파일은 2024년 12월에서 멈춰 있었습니다.
목록 페이지를 먼저 읽고 현재 링크를 찾는 2단계로 갑니다. USDA를 이 방식으로 대체했습니다.

**한 글자 매칭어는 오탐을 냅니다.** 울을 넣었더니 서울에 걸린 사례가 있습니다. 두 글자 미만은 자동으로 무시합니다.
4자 이하 영문 약어는 단어 경계를 강제합니다. dwr이 sandworm에 걸리는 것을 막습니다.

**번역 엔드포인트는 공식 API가 아닙니다.** 막힐 수 있습니다. 막히면 원문 제목이 그대로 나옵니다.
화면은 정상 동작합니다. 나중에 `python run.py translate`로 다시 채우면 됩니다.

**미국 Census 경로는 아직 실측하지 않았습니다.** 키를 발급받은 뒤 `python run.py kpi`로 한 번 확인해야 합니다.
실패해도 나머지 수집은 계속됩니다.

**저장소가 공개입니다.** 사내 실적, 단가, 협력사명을 `kpi_manual.csv`나 설정 파일에 넣지 마십시오.
여기 들어가는 것은 공개된 뉴스와 공시, 정부 통계뿐입니다.
